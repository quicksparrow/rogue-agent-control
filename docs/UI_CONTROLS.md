# Interface interaction audit

The Chromium suite exercises the six workspace routes through their normal navigation, forms and evidence controls. It starts a loopback server with a separate SQLite database, an unavailable local model endpoint, empty catalog credentials and disabled payment configuration. Checkout lifecycle tests intercept browser requests and supply explicitly mocked responses. Provider and catalog link tests fulfill the opened tab locally.

| Surface | Controls exercised | Observable result |
| --- | --- | --- |
| Workspace navigation | Brand, all six primary destinations, contextual links, keyboard skip, mobile Menu, Escape and current-page indicator | Expected route and heading, focus on the main content or restored to the menu toggle |
| Black Box | Consumer and B2B quick recording, new recording dialog, both persona and outcome choices, submit, close and Escape, run selection, refresh and retry | Saved synthetic recording, correct selected run, feedback during loading and failure, form locked during a pending submission |
| Timeline and inspector | Timeline/Explorer switch, individual event buttons, slash search shortcut, actor filter, Clear filters, parent link, visibility-gap event link, correlation, capture instructions and limitations disclosures | Filters affect the displayed events, related-event navigation selects the original stored record, expandable details work from the keyboard |
| AG Grid Community | Row click, Enter on a focused cell, column sorting, column filter popup, independent search and source filter, horizontal scrolling, citation selection | Sorted and filtered rows, visible empty state, technical reference columns and the exact selected event restored from a citation |
| Shopping agent | Scenario, catalog mode, owner policy version, objective, budget, currency, quantity, preferences and merchant references, Check status, Run shopping agent, Black Box and policy links | Submitted values match the form, exact money validation is visible, model/catalog failure retains the saved mandate and chosen mode, pending requests lock submission |
| Shopping results | Product evidence, catalog source link, immutable mandate/identity details, Firewall decision details, Open Black Box | Reference details expand, the test catalog opens in a separate intercepted tab, the Black Box link selects the original run |
| Firewall | Policy version selector, label, limit, currency, quantity bounds, mismatch outcome, automatic authority, human review, every allowed/prohibited merchant checkbox, save, Evaluate A through E and fixture evidence link | Stored version changes only on successful save, selected controls reach the API with integer minor units, five expected outcomes appear and link to original evidence |
| Investigation | Open Black Box, section links, snapshot, additional observations, history, report generation, fact citations | Same-run event ID in the destination inspector, recorded findings still visible when model generation fails, original snapshot and artifact metadata available |
| Replay | Recorded proposal, both what-if mismatch options, Compare policies | Identical proposal compared under the selected alternative, baseline match displayed, REVIEW/REVIEW and REVIEW/DENY comparisons covered |
| Sandbox checkout | Create, buyer link, verify, capture, local cancel, retry original create, mapping references, inspect payment evidence and return to shopping | Mock lifecycle transitions, approval and capture remain distinct, five delayed error paths check pending locks, one request per double-click, recovery and retained context |
| Guided demo | All four scenarios, retry after a failed load, section links, source selection, search, evidence citations, shopping/Black Box links | Selected scenario and provenance remain visible, snapshot loads without executing financial operations, cited evidence is selected even after filters hide it |

The application currently has no application-owned copy or download buttons. Persisted JSON is selectable browser text. Clipboard and file-export workflows do not appear in the control inventory.

The suite checks families of controls with generated records, including multiple recording types and conditional payment states. It does not enumerate every possible historical database value, third-party grid menu combination, assistive technology or device. The visual review and verification counts are recorded in the project implementation plan.
